## 2025-02-18 - IDOR in AlertMarkReadView
**Vulnerability:** The `AlertMarkReadView` in `alertas/views.py` used `get_object_or_404(Alert, pk=pk)` without enforcing department-level isolation for non-admin users. This allowed any logged-in non-admin user (with the `encargado` role) to mark any other department's alert as read via an IDOR (Insecure Direct Object Reference).
**Learning:** When custom view classes inherit from django's base `View` and manually implement request methods like `post` instead of using Django's generic editing views, they do not automatically benefit from `DepartmentFilterMixin` or other generic queryset/object-filtering hooks. This can lead to security oversights if the developer assumes mixins or default queryset overrides are applied everywhere automatically.
**Prevention:** Always ensure that direct database lookups (e.g., using `get_object_or_404` or direct `.get()` calls) inside manual `View` handlers validate the object's relationship to the user's current scope (such as department or owner). Explicitly filter the queryset by user-associated attributes before retrieving the object.
