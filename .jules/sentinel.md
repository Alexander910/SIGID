## 2026-10-08 - IDOR in View classes bypassing DepartmentFilterMixin
**Vulnerability:** `AlertMarkReadView` directly fetched an `Alert` model instance using `get_object_or_404(Alert, pk=pk)` without restricting the queryset to the authenticated user's department for non-admin users. This allowed users with 'encargado' role from one department to mark alerts belonging to other departments as read by manipulating the URL parameter `pk`.
**Learning:** Generic views like `ListView`, `UpdateView`, and `DeleteView` work seamlessly with `DepartmentFilterMixin`, but non-generic `View` instances implementing explicit `post` methods bypass `DepartmentFilterMixin.get_queryset()`. Manual filtering on `Alert.objects.filter(product__department=user.department)` is required before fetching objects in custom `View` actions.
**Prevention:** When implementing custom action `View` classes (such as POST action views for state updates), always construct a scoped queryset filtered by tenant/department before calling `get_object_or_404`.
