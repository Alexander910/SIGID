## 2025-02-18 - IDOR in View-Based Post Request Handlers
**Vulnerability:** Django views inheriting from base `View` that implement manual `post` methods (like `AlertMarkReadView` in `alertas/views.py`) bypass standard queryset filter mixins (such as `DepartmentFilterMixin` which filters `get_queryset`). This allows users to perform unauthorized actions on arbitrary records by direct primary key manipulation (IDOR).
**Learning:** Mixins like `DepartmentFilterMixin` only intercept the `get_queryset` method commonly used by generic views (e.g., `ListView`, `UpdateView`). When a view uses a manual `post` method and calls `get_object_or_404(Model, pk=pk)` directly, it doesn't utilize `get_queryset` filtering, thus bypassing database isolation controls.
**Prevention:** Always manually apply department-based filtering using `request.user.department` (or standard role/department checks) in generic `View` endpoints or any custom action endpoint that does not leverage a standard filtered queryset.
