## 2026-07-23 - IDOR in AlertMarkReadView due to View Inheritance bypassing Mixin
**Vulnerability:** Insecure Direct Object Reference (IDOR) in `AlertMarkReadView` where non-admin users could mark any system alert as read by sending a POST request with the alert's primary key (`pk`).
**Learning:** Unlike generic Django views that automatically utilize `DepartmentFilterMixin` via `get_queryset`, custom `View` subclasses implementing manual `post` methods (without utilizing `get_queryset`) bypass standard department-level queryset isolation. These views retrieve objects directly using unfiltered managers (like `get_object_or_404(Alert, pk=pk)`), causing IDOR.
**Prevention:** Always restrict querysets manually inside non-generic `View` methods before calling retrieval helpers. Perform a check against the user's role (e.g. `request.user.role != 'admin'`) and filter by `product__department=request.user.department` (or relevant foreign key path) to ensure appropriate tenant-like or department-level isolation.
