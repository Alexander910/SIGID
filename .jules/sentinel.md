## 2026-09-30 - IDOR Bypass in Base View Direct Subclasses
**Vulnerability:** `AlertMarkReadView` inherited from Django's base `View` rather than `DepartmentFilterMixin` or generic views, and used `get_object_or_404(Alert, pk=pk)` without scoping the queryset by department. This allowed non-admin users from one department to mark alerts from another department as read (IDOR).
**Learning:** Generic view mixins like `DepartmentFilterMixin` only automatically apply when class-based views use standard `get_queryset()` methods (such as `ListView`, `DetailView`, `UpdateView`). Views inheriting directly from `django.views.View` with custom `post()` methods bypass mixin query filtering unless querysets are explicitly scoped within the method handler.
**Prevention:** Always explicitly construct a filtered queryset using the user's department relation (e.g. `product__department=request.user.department` for non-admin users) prior to invoking `get_object_or_404()` in manual POST or custom handlers.
