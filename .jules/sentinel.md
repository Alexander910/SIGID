## 2025-02-14 - IDOR Vulnerability via Direct Object Lookup in Manual Django View Methods
**Vulnerability:** The `AlertMarkReadView` had a direct object lookup pattern via `get_object_or_404(Alert, pk=pk)`. This allowed any authenticated user to perform an Insecure Direct Object Reference (IDOR) and mark any alert in the database as read, bypassing department-level data isolation.
**Learning:** Generic views utilizing the `DepartmentFilterMixin` correctly filter querysets on `get` and `post` because they hook into Django's standard query dispatch. However, manual View subclasses with custom `post()` methods bypass this automatically-applied queryset filtering, making them highly susceptible to direct ID lookups.
**Prevention:** Avoid performing direct model lookup (e.g., `get_object_or_404(Model, pk=pk)`) in views with manual custom action methods. Instead, explicitly pass a pre-filtered queryset matching the user's department restriction or other multi-tenant scopes to ensure isolation is enforced before the object is retrieved.
