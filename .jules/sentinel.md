## 2026-07-19 - Insecure Direct Object Reference (IDOR) in AlertMarkReadView
**Vulnerability:** The `AlertMarkReadView` class-based view processed single alert status updates via POST requests using `get_object_or_404(Alert, pk=pk)` but lacked department filtering constraints for non-admin users. This allowed unauthorized users to mark alerts belonging to different departments as read simply by guessing/providing the alert ID.
**Learning:** Generic views like `ListView` that use `DepartmentFilterMixin` correctly restrict object querysets by department. However, views inheriting from Django's base `View` that implement custom HTTP methods (e.g., `post`) bypass `DepartmentFilterMixin` methods and must explicitly apply queryset constraints.
**Prevention:** Always restrict querysets used for object retrieval in all views (especially those handling modifications) using explicit filters like `.filter(product__department=request.user.department)` for non-admin roles before using `get_object_or_404`.
